# Markdown記述・検査ルール

## 日本語本文

- 通常の日本語本文では、一つの文を一つの物理行に記述し、句点`。`の後で改行する。
- 閉じかぎ括弧などが句点の直後にある場合は、閉じ記号の後で改行する。
- 同じ段落内で次の文が続く行は、行末に半角スペース2個を置き、Viewer上でも改行を表示する。  
  文間に空行は入れず、段落末や別のリスト項目の直前には行末スペースを置かない。
- 見出し、リスト、引用でも、文章を含む場合は同じ規則を使う。
- 表のセルには句点を含む長文を置かず、短い句点なしの表現にするか本文・リストへ移す。

## 検査対象外の構文

YAML frontmatter、fenced code、インデントされたコード、インラインコード、URL、リンク先、参照リンク先、HTMLタグ、Markdown表、生成物のディレクトリは本文規則から除外する。  
リンクの表示文字列は本文として扱う。  
検査器は構文上安全に判別できる範囲だけを自動修正し、残る指摘は手で修正する。

## 検査コマンド

- 通常の文書変更では `python3 scripts/check-docs.py` を実行する。  
  staged、unstaged、未追跡、rename後のMarkdownを重複なく検査する。
- CIでは比較元を指定して `python3 scripts/check-docs.py --ci --base <比較元>` を実行する。
- 明示したファイルだけを検査する場合は `python3 scripts/check-docs.py <ファイル...>` を実行する。
- 規則変更時や監査時に限り `python3 scripts/check-docs.py --all` を実行する。
- 安全に分割できる文章と表示用改行を修正する場合は、選択オプションまたはファイル指定に `--fix` を追加する。

`MDJ001`は句点改行違反を`file:line`で示す。  
`MDJ002`は同じ段落内で次の文が続く行の行末スペース不足を`file:line`で示す。  
`MDL001`は相対リンク先の欠落を`file:line`で示す。  
リンク先のファイルまたはディレクトリの存在を検査し、外部URL、サイトルートからのパス、ページ内アンカー、見出しアンカーの一致は検査しない。  
同じ入口でマシンローカルな絶対パスも検査する。  
Python 3.9以上の標準ライブラリとリポジトリ内のスクリプトだけを使用する。  
検査器の版はGitのコミットで固定し、フロントエンドの依存には含めない。
