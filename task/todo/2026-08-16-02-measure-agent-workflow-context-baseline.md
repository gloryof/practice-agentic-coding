# Agentワークフローのコンテキスト基準値を計測する

## ステータス
- Status: Proposed
- Updated: 2026-08-23 - 一言で計測を開始し、隔離した作業Agentの結果を保存するSkillを追加
- Updated: 2026-08-23 - 標準計測を作業着手前までとし、代表シナリオだけ完全実行する二段構成へ変更
- Updated: 2026-08-16 - 起票

## 背景
実装タスクでは、ルートと対象ディレクトリの`AGENTS.md`、実装フロー、開発ガイド、詳細規則、仕様、スキル、レビュー資料、コードを段階的に参照する。現時点では、どの工程でコンテキストが増え、必要な参照と重複参照がそれぞれどの程度を占めるかを比較できる基準値がない。

既存フローには対象領域分類、仕様影響ゲート、条件付きレビューが存在するため、改善前の状態を記録せずに仕組みを変更すると、既存施策の効果と新しい施策の効果を区別できない。

学習目的で全シナリオを実装、レビュー、検証まで毎回実行すると、1回の計測時間が長くなり、改善と再計測の反復回数を確保できない。日常的な計測では作業着手前のコンテキスト選択と計画品質へ対象を絞り、節目だけ代表シナリオを完全実行する必要がある。

## 影響
総トークン数だけを根拠に文書やレビューを削減すると、品質維持に必要なガードレールまで弱める可能性がある。基準値がなければ、コンテキスト選択の改善後に品質を維持したまま不要な読み込みを減らせたか判断できない。

## 対応案
- 次の8シナリオを、再実行可能な入力、対象領域、安定した成果物評価観点とともに定義する。特定のフロー名、スキル、参照文書を静的な正解として固定しない。
  - コード調査。
  - 軽微変更。
  - ユーザーストーリー作成。
  - ドメインモデル仕様作成。
  - 固定仕様を入力とするAPI実装。
  - 固定仕様を入力とするフロントエンド実装。
  - APIアーキテクチャ方針変更。
  - フロントエンドアーキテクチャ方針変更。
- 標準計測はリポジトリを変更しない`pre-work`とし、調査結果、仕様案、または実装担当が追加判断せず着手できる作業計画の完成までを対象とする。
- 基準値確定時と主要な改善後だけ、`05-api-implementation`を`full-run`として実装、レビュー、検証、最終報告まで実行する。
- `pre-work`では初期コンテキスト、フロー選択、文書読み込み、コード探索、着手前成果物作成の各段階を記録する。`full-run`では実装、レビュー、検証を追加で記録する。
- 各参照を`required`、`conditional-required`、`unnecessary`、`duplicate`のいずれかに分類できる判定基準を定義する。
- トークン数を直接取得できない環境では、読み込んだ文書・コードの行数または概算トークン数を代替指標として記録し、実測値と混同しない。
- 改善指標として総量だけでなく、`required context / total context`の割合、同一資料の重複探索回数、呼び出したスキル、参照した文書、予定したレビューと検証、実行したレビュー数、完了条件の見落とし有無を残す。
- 計測手順と結果の保存場所を決め、後続TODOから同じシナリオと形式を再利用できるようにする。
- `.codex/skills/agent-workflow-benchmark/SKILL.md`を計測Coordinatorの入口とし、自然文の依頼から隔離した作業Agentを起動して、一実行一シナリオの結果を保存する。

## 確認方法
- 8つの代表シナリオについて、同じ入力から同じ実行モードと`pre-work`の計測区間を再現でき、選択されたフロー、スキル、参照文書と根拠が記録される。
- 各シナリオで、リポジトリを変更せず、期待する調査結果、仕様案、または着手可能な作業計画が作成される。
- 各シナリオに必要なガードレールと不要・重複コンテキストの根拠が記録される。
- `05-api-implementation`の`full-run`について、実装、レビュー、検証を含む基準値が保存される。
- 計測不能な値と代替指標が明確に区別される。
- 後続の改善前後で比較できる基準値が保存される。
- 文書変更後に`./scripts/check-no-local-paths.sh`が成功する。
