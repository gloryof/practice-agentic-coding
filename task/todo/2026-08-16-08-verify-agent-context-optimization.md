# Agentコンテキスト最適化の効果を再計測する

## ステータス
- Status: Proposed
- Updated: 2026-08-23 - 着手前の全シナリオと代表シナリオの完全実行を分離して再計測する方針へ変更
- Updated: 2026-08-16 - 起票

## 背景
コンテキスト選択、Review Context Package、ワークフローとレビューの選択を導入しても、改善前と同じ条件で再計測しなければ、コンテキスト使用量、重複探索、処理時間を減らしながら品質を維持できたか判断できない。

個別施策が局所的に読み込みを減らしても、選択用の索引、構造化出力、回帰検査が新たなオーバーヘッドとなり、全体では改善しない可能性がある。

## 影響
効果が未確認のまま運用を固定すると、必要なガードレールを維持しただけで処理が複雑化したり、逆にトークン削減を優先して必要なレビューを欠落させたりする可能性がある。

## 対応案
- `task/todo/2026-08-16-02-measure-agent-workflow-context-baseline.md`で定義した8シナリオについて、同一入力、区間、指標を使って`pre-work`を再計測する。
- `05-api-implementation`だけを`full-run`で再計測し、実装、レビュー、検証を含む改善前後の差分を確認する。
- `pre-work`では総コンテキスト、必要コンテキスト率、重複探索回数、呼び出したスキル、参照文書、予定したレビューと検証、処理時間、完了条件の見落とし有無を比較する。
- `full-run`では予定と実際のスキル、レビュー、検証の差分、回帰検査結果、追加コンテキストを比較する。
- Main Agentと各レビュアーの使用量を分け、Review Context Packageによって移動または増加したコストを全体値から隠さない。
- `trivial`、`normal`、`complex`ごとに、削減効果と品質維持の結果を整理する。
- 必須文書、必須レビュー、必須検証の欠落がある施策は、トークン削減量にかかわらず不採用または修正する。
- 効果が小さい、または選択処理の方が高コストな箇所は、索引、分類条件、パッケージ形式の簡素化候補として記録する。
- 計測結果から新しい未解決リスクが見つかった場合だけ、重複確認後に別TODOを起票する。

## 確認方法
- 8シナリオの`pre-work`について、改善前後を同一条件で比較した結果が保存される。
- `05-api-implementation`の`full-run`について、改善前後を同一条件で比較した結果が保存される。
- 総量だけでなく、必要コンテキスト率、着手前の計画品質、Main Agent・レビュアーを合わせた完全実行時の全体コストを確認できる。
- 回帰ケースが成功し、必要な規則、予定または実行すべきレビュー、検証、完了条件の欠落がない。
- 各施策について維持、修正、撤去の判断と根拠が記録される。
- 文書変更後に`./scripts/check-no-local-paths.sh`が成功する。
