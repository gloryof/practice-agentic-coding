# API起動コマンドとE2E実行手順のスキル化

## ステータス
- Status: Proposed
- Updated: 2026-05-24 - 起票

## 背景
- API起動コマンドとE2E実行手順が個別ノウハウ化しており、毎回の実行手順が属人化しやすい。
- 手順の揺れにより、検証前提の不一致や再現性低下が発生しうる。

## 影響
- 実行者ごとにコマンドや前提確認が異なり、失敗時の原因切り分けコストが増える。
- E2E検証のオンボーディング負荷が高くなり、変更確認のリードタイムが延びる。
- CI/ローカルでの実行差分が放置されると、品質判断の一貫性が下がる。

## 対応案
- API起動からE2E実行までの標準手順をスキルとして定義する。
- 前提条件チェック（依存サービス、環境変数、DB状態など）をスキル内に明文化する。
- 失敗時の典型パターンと復旧手順をトラブルシュートとして含める。
- 最低限の実行コマンド例（ローカル検証用）と期待結果を定義し、再現性を担保する。

## 確認方法
- 新規メンバー想定で、スキル記載のみを参照してAPI起動とE2E実行が完了できることを確認する。
- 既存メンバー2名以上で手順をトレースし、実行結果と観測ログが一致することを確認する。
- 手順通りに実施した際、主要な失敗ケースでトラブルシュート記載により復旧できることを確認する。
