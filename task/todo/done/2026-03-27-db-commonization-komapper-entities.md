# DBアクセス共通化（KomapperEntity定義・Metaクローンのテーブル名）

## ステータス
- Status: Done
- Updated: 2026-03-27 - 起票
- Updated: 2026-05-10 - 完了

## 背景
- Catalog検索のKomapper化に伴い、KomapperEntity定義とMetaのクローン時テーブル名が各実装に散在し始めている。
- Queryの条件構築も個別実装が増えやすく、表現の揺れや再利用性低下が懸念される。
- 参照系/更新系で同様の定義が増えると差分や命名揺れが起きやすい。

## 影響
- DBアクセスの一貫性低下（テーブル名・カラム名の揺れ）。
- Query条件構築の重複により、検索仕様の実装差分が生じやすい。
- 将来のスキーマ変更時に修正漏れが発生しやすくなる。

## 対応案
- KomapperEntity定義の配置方針と命名規約を整理し、共通化方針を決める。
- Metaクローン時のテーブル名を一元管理する仕組み（定数/拡張関数/共通ファクトリなど）を設計する。
- 既存のKomapperEntityとクローン箇所を棚卸しし、共通化方針に合わせて再配置・統一する。
- Query条件構築の共通化方針（共通DSL/ヘルパー/Specification等）を検討し、既存条件式を共通化する。

## 確認方法
- KomapperEntity定義とMetaクローン箇所の一覧が作成され、命名・テーブル名が統一されていること。
- `./gradlew check` が通ること。
