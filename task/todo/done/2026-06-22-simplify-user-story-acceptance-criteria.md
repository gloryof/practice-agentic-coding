# ユーザーストーリーの受け入れ条件をユーザー価値の粒度へ見直す

## ステータス
- Status: Done
- Updated: 2026-06-22 - 起票
- Updated: 2026-07-11 - 今後作成または更新するユーザーストーリーの記載方針を整備して完了

## 背景
現在のユーザーストーリーには、HTTPステータス、項目単位の入力チェック、内部処理の失敗時動作など、ユーザー価値の確認を超えた詳細が受け入れ条件に含まれている。これらの詳細はユースケース仕様、API仕様、テスト設計で管理すべき内容と重複しやすい。

## 影響
受け入れ条件が細かすぎると、ユーザーストーリーから実現したい価値と完了状態を読み取りにくくなる。また、実装詳細の変更によってユーザー価値が変わらない場合でもストーリー更新が必要となり、仕様間の不整合や保守負荷が増える。

## 対応案
- 受け入れ条件は、図書館利用者または司書が確認できる成果と、ユーザー価値の成立に不可欠な業務ルールに限定する。
- HTTPステータス、入力形式、項目別エラー、トランザクション、内部障害時の応答などは、該当するユースケース仕様または実装仕様で管理する。
- `task/user-stories/TEMPLATE.md` と `task/user-stories/README.md` に、受け入れ条件の適切な粒度と記載対象外を明記する。
- 本方針は今後作成または更新するユーザーストーリーに適用し、既存のユーザーストーリーには遡及適用しない。

## 確認方法
- `task/user-stories/TEMPLATE.md` と `task/user-stories/README.md` で、受け入れ条件の適切な粒度と記載対象外が一致していることを確認する。
- 既存のユーザーストーリーが変更されていないことを確認する。

## 期限 / 優先度
- 期限: 次のユーザーストーリー作成または既存ストーリー更新前
- 優先度: Medium
