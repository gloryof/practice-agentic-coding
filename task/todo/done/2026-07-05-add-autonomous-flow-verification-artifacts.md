# 自走フローの検証成果物追加

## ステータス
- Status: Done
- Updated: 2026-07-05 - 起票
- Updated: 2026-07-12 - E2E テストと動作確認用スクリプトを実装自走フローの原則必須成果物として追加

## 背景
起票時の実装自走フローでは、対象機能の単体テスト、ユースケーステスト、Web レイヤテスト、DAO/Repository まわりの確認を進めている一方で、利用者操作として API を通しで確認する成果物が不足していた。

具体的には、予約申込機能について以下が未整備であることを課題としていた。

- E2E テストが実装されていない。
- 動作確認用のスクリプトが追加されていない。

## 影響
単体・レイヤ別テストでは、認証、HTTP リクエスト、予約申込 API、永続化、レスポンス形式を一連の利用者操作として接続できることを確認しきれない。

また、動作確認用スクリプトがないため、ローカル API 起動後に手動で同じ確認を再現する手順が属人的になりやすい。今後の自走実装で、機能追加後に「実際に利用者操作として動くか」を確認する粒度が揺れる。

## 対応案
予約申込機能について、外部起動済み API に対する E2E テストを追加した。E2E では、利用者登録、ログイン、認証付き予約申込、正常レスポンスを主要フローとして確認する。代表的な業務エラーは、重要な回帰リスクがある場合に `api/docs/test-policy.md` に従って追加する。

あわせて、ローカル動作確認用の `api/scripts/verify-place-reservation.sh` を追加した。スクリプトは、既存の API 起動・E2E 実行方針と競合しないようにし、必要な入力、前提データ、期待する HTTP ステータスと主要レスポンス項目を明確にした。

実装自走フローでは、ユーザー操作に直結する API を追加・変更した場合、以下を原則必須の完了条件とした。

- E2E テストを追加または更新する必要があるか。
- ローカル動作確認用スクリプトを追加または更新する必要があるか。
- 既存成果物を再利用する場合、その理由と実行結果を完了報告に残しているか。
- 必要な成果物または実行が未完了の場合、未解決リスクとして TODO を起票しているか。

## 確認方法
`api` ディレクトリで対象 E2E テストを実行し、予約申込の主要フローが HTTP 経由で成功することを確認する。

動作確認用スクリプトは、ローカル API 起動済みの状態で実行し、期待する HTTP ステータスと主要レスポンス項目を確認できることを検証する。

## 期限 / 優先度
優先度: 中。予約申込 API を利用者操作として確認する前、または予約申込機能を完了扱いにする前に対応する。
