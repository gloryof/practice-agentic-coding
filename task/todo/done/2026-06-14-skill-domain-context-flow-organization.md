# スキルごとのドメイン仕様参照フロー整理

## ステータス
- Status: Done
- Updated: 2026-06-14 - 起票
- Updated: 2026-06-21 - スキルごとの仕様参照、更新責務、引き継ぎ条件を整理

## 背景
- 仕様の正本を `product/domain-context` に統合したことで、各スキルが仕様を参照・作成・更新する場面と責務を見直す必要がある。
- 現状は `product/domain-context` と各スキルの必須入力、ワークフロー、出力契約の関係が統一されていない。
- 仕様作成、仕様更新、仕様Q&A、ユーザーストーリー作成、実装、各種レビューで、仕様参照や更新要否の判断がスキルごとに分かれる可能性がある。

## 影響
- `product/domain-context` の確認漏れや更新漏れが発生し、仕様と成果物が乖離する可能性がある。
- 複数スキルが同じ仕様更新を担当したり、どのスキルも担当しなかったりする責務の重複・空白が生じる。
- スキル間の引き継ぎ条件が不明確になり、作業の手戻りや判断のばらつきにつながる。

## 対応案
- `po-story` と `po-spec` に、`product/domain-context` の探索、仕様参照、必要な正本文書の更新手順を整備した。
- 実装フローに、実装前の仕様確認と振る舞い・契約変更時の正本文書更新責務を整備した。
- 各レビュースキルに、関連仕様をレビュー基準として参照し、不整合や更新必要性を呼び出し元のPOまたは実装フローへ引き継ぐ手順を追加した。
- 各レビュースキルは仕様を決定・更新しない責務境界を明記し、POおよび実装フローとの重複を解消した。

## 確認方法
- `po-story` と `po-spec` が仕様判断前に関連するユーザーストーリーとドメイン仕様を参照し、変更時は正本文書を更新することを確認した。
- 実装フローが実装前に関連仕様を参照し、振る舞いまたは契約の変更時に正本文書を更新することを確認した。
- 各レビュースキルが関連仕様を参照し、仕様更新を直接行わず、必要な対応を呼び出し元へ引き継ぐことを確認した。
- 既存の固定出力契約を変更せず、フローと各 `SKILL.md` の責務が整合していることを確認した。
