# コマンドのコンテキスト境界を跨ぐ依存を解消する

## ステータス
- Status: Done
- Updated: 2026-07-11 - 起票
- Updated: 2026-07-18 - コンテキスト固有型と認証情報発行契約へ移行し、直接依存を解消

## 背景
`api/docs/architecture.md` は、コマンド側でコンテキスト境界を跨いだ依存を禁止している。一方、現行実装には `auth` から `libraryuser`、`reservation` から `libraryuser`、`libraryuser` から `auth` のドメイン型、Repository、Domain Serviceへの直接依存があった。

代表例として、認証アカウントが `libraryuser` のメールアドレスと図書館利用者IDを参照し、予約モデルが `libraryuser` の図書館利用者IDを参照していた。また、図書館利用者登録のイベントハンドラーが `auth` の認証資格情報、Repository、パスワードハッシュ処理へ直接依存していた。

## 影響
コンテキスト間でドメイン型とポートを直接共有すると、一方のモデル変更が別コンテキストへ伝播し、コンテキスト単位の変更、テスト、将来の分離が難しくなる。現状はアーキテクチャの `MUST NOT` に違反しており、新しい越境依存を一貫してレビューできない状態だった。

## 対応案
- `auth`、`libraryuser`、`reservation` が、それぞれのコンテキストでメールアドレス、入力パスワード、図書館利用者IDの型を所有する構成へ変更した。
- 認証セッションなどの境界では文字列IDを受け渡し、受信したコンテキストで固有型へ変換するようにした。
- 図書館利用者登録から認証情報を作成する連携は、`shared.auth` の公開契約を介して `auth` のInfraへ委譲した。
- 生パスワードを図書館利用者登録イベントから削除し、ログやイベントへ残さず認証コンテキストで検証、ハッシュ化、保存する構成にした。
- `AuthAccountRepositoryImpl` を `auth` のInfraへ移し、共有DAOの値をauth固有型へ変換するようにした。

## 確認方法
- `auth`、`libraryuser`、`reservation` のDomain、Usecase、Infraに、他コンテキストの `command` パッケージへの直接importがないことを確認する。
- 登録、ログイン、予約の単体テスト、E2Eテスト、ローカル確認スクリプトが成功することを確認する。
- 後続のArchUnit検査で、コンテキスト境界違反を意図的に追加したfixtureが失敗することを確認する。
