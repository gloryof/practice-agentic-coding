# API起動コマンドとE2E実行手順のスキル化

## ステータス
- Status: Done
- Updated: 2026-05-24 - 起票
- Updated: 2026-06-09 - API起動・E2E実行スキルとランナーを追加

## 背景
- API起動コマンドとE2E実行手順が個別ノウハウ化しており、毎回の実行手順が属人化しやすい。
- 手順の揺れにより、検証前提の不一致や再現性低下が発生しうる。

## 影響
- 実行者ごとにコマンドや前提確認が異なり、失敗時の原因切り分けコストが増える。
- E2E検証のオンボーディング負荷が高くなり、変更確認のリードタイムが延びる。
- CI/ローカルでの実行差分が放置されると、品質判断の一貫性が下がる。

## 対応案
- `.codex/skills/run-api-e2e` にAPI起動からE2E実行までの標準手順を定義した。
- `start`、`e2e`、`stop` を提供するランナーで、DB初期化、migration、seed、API起動、health確認、E2E、後片付けを統一した。
- Docker、Java、ポート、Compose管理対象を検査し、既存プロセスや管理外コンテナを変更しない安全策を追加した。
- 典型的な失敗原因と復旧手順をトラブルシュートとして追加した。

## 確認方法
- `start` でDB初期化、migration、seed、API起動を行い、healthが `UP` になることを確認した。
- `e2e` でE2Eテストが毎回実行され、成功後にAPIとPostgreSQLが削除されることを確認した。
- ポート `8080` が使用中の場合、DBを変更する前にエラー終了することを確認した。
- CodexのスキルValidator、シェル構文検査、ローカル絶対パス検査が成功することを確認した。
