# 運用・非機能前提の正本を追加する

## ステータス
- Status: Done
- Updated: 2026-07-20 - 横断的な運用・非機能ベースラインと条件付き参照を追加
- Updated: 2026-07-18 - 起票

## 背景
アーキテクチャ、セキュリティ、DBの各レビュースキルは、想定トラフィック、レイテンシ、可用性、デプロイ、監視、データ保護、バックアップなどを判断材料として要求するが、現在の前提をまとめた正本がない。

## 影響
設計レビューのたびに前提を推測または再確認する必要があり、判断の再現性が下がる。未決定事項が暗黙のまま、過剰設計または必要な対策の見落としにつながる可能性がある。

## 対応案
- 現在のデプロイ形態、利用規模、性能・可用性目標、監視、障害対応、データ分類・保持、バックアップ・復旧、運用担当をまとめる短い正本文書を追加する。
- 決まっていない項目は推測で埋めず、未決定と判断が必要になる条件を明記する。
- `product/product-foundation.md` とAPI実装規約の責務を侵食しない配置とする。
- アーキテクチャ、セキュリティ、DBの設計またはレビュー時だけ参照する条件を入口文書へ追加する。

## 確認方法
- 各レビュースキルの必要入力について、正本、タスク固有情報、未決定のいずれかを区別できることを確認する。
- 通常の機能実装や文言修正では、この文書が必須参照にならないことを確認する。
- `./scripts/check-no-local-paths.sh` を実行する。
