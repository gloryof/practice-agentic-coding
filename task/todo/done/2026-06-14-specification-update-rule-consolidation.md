# 仕様更新ルールの正本統合

## ステータス
- Status: Done
- Updated: 2026-06-14 - 起票
- Updated: 2026-06-21 - 仕様更新ルールの正本を追加し、AGENTS、フロー、探索ガイド、POスキルの重複記述を参照へ統合
- Updated: 2026-06-21 - HTTPインターフェースを実装設計として仕様更新ルールの対象外に整理

## 背景
- 仕様更新時に更新すべき文書と責務が、ルート `AGENTS.md` の「仕様更新ルール」と `product/domain-context/README.md` の「更新ルール」に重複して記載されている。
- 同様の内容が `agents/flows/user-story-creation-flow.md` と `agents/flows/implementation-task-flow.md` にも記載されている。
- 現状は、どの文書が仕様更新ルールの正本で、どの文書が作業フロー上の参照先なのかが明確でない。

## 影響
- 仕様更新ルールを変更する際に複数文書の同期が必要となり、更新漏れや内容の乖離が発生しやすい。
- AIや開発者が異なる文書を参照した場合、更新対象や責務について異なる判断をする可能性がある。
- `AGENTS.md` と各フローが詳細ルールを持つことで、参照ハブと実行手順の責務が曖昧になる。

## 対応案
- `agents/rules/specification-update-rules.md` を仕様更新ルールの単一の正本として追加した。
- ユーザー価値、ドメイン仕様、ユーザーストーリー、索引の更新条件と責務を正本文書へ集約した。
- HTTP インターフェースは実装設計として扱い、仕様更新ルールの対象外とした。
- `AGENTS.md` には適用条件と正本文書への参照だけを残した。
- `agents/flows` と PO スキルには各フロー固有の実行手順だけを残し、共通の仕様更新ルールは正本文書を参照する形式にした。
- `product/domain-context/README.md` は探索、構造、文書作成規約に責務を限定した。

## 確認方法
- 仕様更新ルールの詳細が `agents/rules/specification-update-rules.md` だけに記載されていることを確認した。
- `AGENTS.md` と各 `agents/flows` から正本文書へ到達でき、適用する場面を判断できることを確認した。
- 代表的な仕様変更について、正本文書だけで更新対象と責務を一意に判断できることを確認した。
- `rg` で仕様更新ルールの重複記述が残っていないことを確認した。
