# ログの出力を減らしてトークン使用量を減らす

フロントエンドとAPIの主要チェックゲートの詳細出力をファイルへ保存し、端末には結果とログパスだけを表示できるようにした。

## ステータス
- Status: Done
- Updated: 2026-10-18 - 主要チェックゲートのログ保存と検証を完了
- Updated: 2026-10-12 - 起票

## 背景
フロントの実装でトータル316kのトークンを使っている。  
途中までは160kなどだったので実行途中でトークンを消費していると思われる。   

## 課題
E2Eの結果のログなどが毎回AIのInputとして使用されているためトークンが増えている。  
上記はあくまで仮説ではあるが、可能性が高いため対応する。

## 完了条件
- 「実装方法案」に書かれた内容の処理ができていること

本来であれば消費されたトークンが減っていることが完了条件になる。  
ただ、このTODO単体では計測できない。  

よって、このTODOでは実装方法案の実現に止め、次以降の実装フェーズでどうなるかを観測する。

## 実装方法案
サーバサイド/フロントエンド共にチェックゲートのログは必ず別ファイルに出力する。  
そして、実行結果でエラーがある場合だけログを確認して分析できるようにする。

## 対応結果

- フロントエンドの`check`、Chromium E2E、複数ブラウザE2E、性能検査の詳細出力を`work/logs/frontend/`へ保存する。
- APIの`check`、`test`、E2Eの詳細出力を`work/logs/api/`へ保存する。
- 各ログはゲートごとの固定名で上書きし、端末には結果、終了コード、ログパスを表示する。
- フロントエンドとAPIの`check`、APIテスト、API E2E、Chromium E2E、性能検査の成功を確認した。  
  複数ブラウザE2Eはテスト一覧表示で引数転送とログ保存を確認した。
- トークン使用量の変化は後続の実装作業で観測する。
