# 仕様把握のためのドキュメント導線整理

## ステータス
- Status: Done
- Updated: 2026-05-24 - 起票
- Updated: 2026-06-14 - ドメイン仕様の探索ガイド、テンプレート、仕様更新フローを整備

## 背景
- 現状、仕様の全体像や判断根拠がドキュメント上で追いにくく、コードを読まないと仕様を把握できない場面がある。
- その結果、仕様確認の初動が遅れ、実装/レビュー時の認識差分や手戻りリスクが高まる。

## 影響
- 新規参加者や非実装担当者のキャッチアップコストが増加する。
- 仕様確認にコード読解が必須となり、PO/QA/レビューのリードタイムが悪化する。
- 仕様変更時に「どこを更新すべきか」が不明確になり、ドキュメントの陳腐化を招く。

## 対応案
- `product/domain-context/README.md` を仕様の構造と探索方法を示す入口として追加した。
- ユースケース、ドメインモデル、ドメインイベントのテンプレートを追加し、既存文書へ目的、入出力、制約、失敗条件、関連実装とテストを記載した。
- ユーザー価値、ユースケース、ドメインモデル、ドメインイベントを `product/domain-context` の正本へ統合した。
- 仕様フロー、実装フロー、PO仕様スキル、ルート `AGENTS.md` に仕様確認と同時更新のルールを追加した。

## 確認方法
- 図書館利用者登録、ログイン、蔵書検索について、仕様文書だけで目的、入出力、制約、失敗条件、処理フローを確認できる状態にした。
- 探索ガイドと各仕様文書から、関連仕様、モデル、イベント、実装、テストへ辿れることを確認する。
- 仕様変更時に更新すべき正本文書を、仕様フローと実装フローの完了条件へ追加した。
