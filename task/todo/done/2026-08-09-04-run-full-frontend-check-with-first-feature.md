# 初回フロントエンド機能で品質ゲート一式を検証する

## ステータス
- Status: Done
- Updated: 2026-08-16 - 初回利用者機能でクリーン準備後の一括品質ゲートを確認して完了
- Updated: 2026-08-09 - 起票

## 背景
Next.js BFF基盤の構築時点では型検査、静的解析、単体・境界テスト、production build、Storybook build、story・a11y検査を個別に確認した。一方、利用者画面が未実装であるため、ユーザー承認の例外として`npm run check`の一括実行を省略し、初回機能実装で問題があれば修正する方針とした。

## 影響
個別ゲート間の順序依存、生成物の干渉、クリーン環境での一括実行時間や安定性は未確認であり、初回機能実装時にゲート失敗が判明する可能性がある。

## 対応案
- 初回の登録、認証、蔵書検索、在庫確認、予約のいずれかを実装した変更で、Node.js 24と`npm ci`による準備後に`npm run check`を実行する。
- 失敗した場合は基盤設定と機能実装のどちらに原因があるかを切り分け、同じ変更で修正する。
- CI接続を先に実施する場合は、CI上の必須ゲート検証を本TODOの確認に含める。

## 確認方法
- クリーンインストール後の`npm run check`が一括で成功することを確認する。
- 個別ゲートの失敗が同じnpm scriptで再現でき、生成物や実行順序に依存した不安定性がないことを確認する。

## 期限 / 優先度
- 期限: 最初のフロントエンド利用者機能実装時
- 優先度: 高

## 完了内容
- Node.js 24で`npm ci`を実行し、ロックファイルどおりに依存関係を再構築した。
- 続けて`npm run check`を一括実行し、型検査、静的解析、単体・境界テスト、production build、Storybook build、story・a11y検査が成功した。
- 個別ゲート間の生成物干渉や実行順序に起因する失敗がないことを確認した。
