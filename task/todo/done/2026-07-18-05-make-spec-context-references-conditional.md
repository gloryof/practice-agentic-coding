# 仕様コンテキストの参照条件を影響範囲に応じて限定する

## ステータス
- Status: Done
- Updated: 2026-07-19 - 仕様影響ゲートと条件付き参照をフローおよびレビュースキルへ反映
- Updated: 2026-07-18 - 起票

## 背景
`agents/flows/implementation-task-flow.md` は、実装タスク全般で関連ユーザーストーリーとドメイン仕様を確認し、仕様更新ルールを適用する構造になっている。内部リファクタリング、CI修正、開発ツール変更などでは、これらが判断に不要な場合がある。

## 影響
仕様への影響がない作業でも関連文書の探索と読み込みが発生し、初動とトークン消費が増える。一方、参照を単純に省略すると仕様影響の見落としにつながる。

## 対応案
- 作業開始時に、ユーザー向け振る舞い、業務ルール、データの意味、受け入れ条件への影響有無を判定するゲートを設ける。
- 影響がある場合のみ、`product/domain-context/README.md` に従って関連仕様を探索する。
- 仕様の意味または索引情報が変わる場合のみ、`agents/rules/specification-update-rules.md` を適用する。
- 参照を省略した場合は、影響なしと判断した理由を完了報告へ簡潔に記載する。
- 各レビュースキルの仕様参照も、業務仕様がレビュー基準になる場合に限定する。

## 確認方法
- 機能追加、内部リファクタリング、CI修正、DB制約変更の例で参照要否が一意に決まることを確認する。
- 仕様影響のある変更では、従来どおり正本の探索と同時更新が必須になることを確認する。
