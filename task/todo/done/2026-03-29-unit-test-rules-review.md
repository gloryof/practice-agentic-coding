# ユニットテストのルール化整理

## ステータス
- Status: Done
- Updated: 2026-04-05 - 完了

## 背景
最近の実装で、テスト観点の追加やルール化の必要性が明確になったため、
統一ルールとして整理する必要がある。

## 影響
各担当者の判断に依存してテスト粒度が揺れ、レビュー効率と品質にばらつきが出る。

## 対応案
- 以下の項目をユニットテスト規約として整理・明文化する。
  - 一覧/検索の結果がコレクションになる場合は「0件」「複数件」ケースを必須にする。
  - Queryの検索条件は項目ごとに絞り込みテストを作成し、誤カラム指定の回帰を検知する。
  - Validatorは入力項目ごとに正常/異常/trim/exactを検証する。
  - `@Nested` 利用の判断基準（入力項目単位で期待仕様を分けたい場合、ケース数が多く読みやすさを優先する場合）。
  - 適用範囲の整理（Command/Query/Web/Infra どこまでを必須にするか）。
  - 追加: 戻り値の正当性検証と戻り値なしメソッドの副作用検証を共通テスト品質へ追記する。

## 確認方法
- 規約ドキュメントに反映され、レビュー時に参照されること。

## 期限 / 優先度
- 優先度: 中
