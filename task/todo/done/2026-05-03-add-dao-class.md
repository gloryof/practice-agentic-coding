# Daoクラスを追加する

## ステータス
- Status: Done
- Updated: 2026-05-03 - 起票
- Updated: 2026-05-10 - 完了

## 背景
- 現在のクエリ実装では、Komapperのテーブルメタを直接利用したデータ取得ロジックがInfra実装クラス内に集約されている。
- データアクセス責務を明確化し、今後の検索条件追加やクエリ再利用を容易にするため、DAOクラスへの分離を検討する。

## 影響
- `catalog/query/infra` 配下の実装構成（クラス分割）が変更される可能性がある。
- テスト構成（単体/統合）にDAO単位の検証追加が必要になる可能性がある。

## 対応案
- Query向けのDAOクラスを追加し、DBアクセス処理（Komapper QueryDsl組み立て）をDAOへ移譲する。
- 既存Infra実装クラスはUsecaseインターフェース実装と結果整形に責務を限定する。
- 命名・配置は既存の`infra/adapter/persistence`方針と整合する形で決定する。

## 確認方法
- DAO追加後に既存のクエリ関連テストが通過することを確認する。
- API標準チェック（`./api/gradlew -p api ktlintFormat`、`./api/gradlew -p api check`）を実行して回帰がないことを確認する。
