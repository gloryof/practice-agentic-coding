# レビュアーへReview Context Packageを引き渡す

## ステータス
- Status: Proposed
- Updated: 2026-08-16 - 起票

## 背景
アーキテクチャ、セキュリティ、QA、DBAなどのレビューでは、各レビュアーがタスク、関連規則、仕様、変更ファイル、差分を個別に探索すると、Main Agentと同じ資料を繰り返し読み込む可能性がある。現行フローはレビュー担当の選択条件を定義しているが、選択済みコンテキストをレビュー担当へ渡す共通入力契約は定義していない。

## 影響
レビューごとの重複探索は、コンテキスト使用量と処理時間を増やし、レビュアー間で異なる仕様や規則を基準にする原因になる。一方、追加探索を全面的に禁止すると、Main Agentが見落とした重大リスクを検出できない。

## 対応案
- Main Agentが各レビュアーへ渡す`Review Context Package`の最小入力契約を定義する。
- 入力には、依頼、選択済みの対象領域と影響分類、変更ファイル、関連仕様、関連規則、差分または差分要約、既知の検証結果、レビュー観点を含める。
- 大きなファイルや差分を無条件に全文複製せず、レビュー判断に必要な箇所と、必要時に原文へ到達できるリポジトリ相対パスを渡す。
- レビュアーは原則としてパッケージを起点にし、重大な判断に不足する情報がある場合だけ追加探索する。追加探索した対象と理由をレビュー結果へ記録する。
- 複数レビュアーで共通する事実と、アーキテクチャ、セキュリティ、QA、DBA固有の焦点を分離し、同一情報を各依頼文へ重複記載しない。
- 不完全または古いパッケージを鵜呑みにしないため、実際の差分と選択結果の整合確認をレビュアーの初期チェックに含める。
- `task/todo/done/2026-07-18-07-deduplicate-role-and-skill-guidance.md`で確定したロール、スキル、チェックリスト、テンプレートの責務分担を維持する。

## 確認方法
- 同じ変更を複数レビュアーへ渡す例で、共通資料の重複探索回数が減る。
- 各レビュアーが固有の観点と必要な差分へ到達できる。
- パッケージに不足または不整合を意図的に含めた例で、追加探索と不足報告が行われる。
- レビュー結果から、使用した入力、追加探索の対象と理由を追跡できる。
- 既存レビュースキルの固定出力契約と重大度体系が変わらない。
- 文書変更後に`./scripts/check-no-local-paths.sh`が成功する。
