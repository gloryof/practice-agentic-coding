# フロントエンドのAPI・認証連携を定義する

## ステータス
- Status: Proposed
- Updated: 2026-07-20 - 起票

## 背景
現行APIはログイン時にBearerアクセストークンを返すが、ブラウザから利用する際の契約参照、CORS、トークン保持、期限切れ時の振る舞いが決まっていない。

## 影響
認証連携を後から変更すると、ログインだけでなく検索と予約の通信処理、画面遷移、エラー処理を作り直す可能性がある。認証情報を不適切に保持すると漏えいや不正利用につながる。

## 対応案
- 動的OpenAPIの参照方法、型同期、API契約変更の検知方法を決定する。
- ローカル環境でのCORSまたは開発プロキシ、API接続先の設定方法を決定する。
- Bearerトークンの保持場所、ライフサイクル、期限切れ、未認証遷移、ログアウト要否を脅威モデルとともに決定する。
- APIエラーの分類と画面表示への変換、相関識別子の伝播方針を決定する。
- XSS、CSRF、認証情報のログ・ブラウザ保存領域への露出を確認し、必要なサーバー変更とフロント変更を分離する。

## 確認方法
- 登録、ログイン、認証済み検索、予約、期限切れのデータフローを追跡できることを確認する。
- 認証情報の生成、保持、送信、失効の各段階に未決定事項が残っていないことを確認する。
- サーバー側の対応事項とフロント側の対応事項を独立して実装・検証できることを確認する。
