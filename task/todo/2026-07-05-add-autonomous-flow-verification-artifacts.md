# 自走フローの検証成果物追加

## ステータス
- Status: Proposed
- Updated: 2026-07-05 - 起票

## 背景
現在の実装自走フローでは、対象機能の単体テスト、ユースケーステスト、Web レイヤテスト、DAO/Repository まわりの確認を進めている一方で、利用者操作として API を通しで確認する成果物が不足している。

具体的には、今回の予約申込機能について以下が未整備である。

- E2E テストが実装されていない。
- 動作確認用のスクリプトが追加されていない。

## 影響
単体・レイヤ別テストでは、認証、HTTP リクエスト、予約申込 API、永続化、レスポンス形式を一連の利用者操作として接続できることを確認しきれない。

また、動作確認用スクリプトがないため、ローカル API 起動後に手動で同じ確認を再現する手順が属人的になりやすい。今後の自走実装で、機能追加後に「実際に利用者操作として動くか」を確認する粒度が揺れる。

## 対応案
予約申込機能について、外部起動済み API に対する E2E テストを追加する。E2E では、利用者登録またはログイン、認証付き予約申込、正常レスポンス、代表的な業務エラーを主要フローとして確認する。

あわせて、ローカル動作確認用のスクリプトを追加する。スクリプトは、既存の API 起動・E2E 実行方針と競合しないようにし、必要な入力、前提データ、実行コマンド、期待する HTTP ステータスと主要レスポンス項目を明確にする。

今後の実装自走フローでは、ユーザー操作に直結する API を追加・変更した場合、以下を完了条件に含めるかを判定する。

- E2E テストを追加または更新する必要があるか。
- ローカル動作確認用スクリプトを追加または更新する必要があるか。
- 追加しない場合、その理由を完了報告または TODO に残しているか。

## 確認方法
`api` ディレクトリで対象 E2E テストを実行し、予約申込の主要フローが HTTP 経由で成功することを確認する。

動作確認用スクリプトは、ローカル API 起動済みの状態で実行し、期待する HTTP ステータスと主要レスポンス項目を確認できることを検証する。

## 期限 / 優先度
優先度: 中。予約申込 API を利用者操作として確認する前、または予約申込機能を完了扱いにする前に対応する。
