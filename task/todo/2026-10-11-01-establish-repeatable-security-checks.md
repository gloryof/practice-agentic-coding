# 既存コードのセキュリティを確認し、定期的に再確認できる状態にする

APIとフロントエンドを対象に、既存コードのセキュリティ確認と、新たな脆弱性を継続して検知するための再実行可能な手順を整備する。

## ステータス
- Status: Proposed
- Updated: 2026-10-11 - 起票

## 背景

実装時のセキュリティ対策に加え、フロントエンドには依存関係の既知脆弱性を調べる`npm run audit:high`がある。  
一方、既存のAPIとフロントエンド全体について、実装後に繰り返しセキュリティを確認する共通の手順と結果の記録方法は定まっていない。  
新たな脆弱性が公開される可能性があるため、実装時点の確認だけでは継続的な把握が難しい。

## 課題

既存コード、設定、依存関係の確認範囲が定まっておらず、後から公開された脆弱性や実装上の問題を見落とすおそれがある。  
定期実行の準備と検出結果の扱いが定まっていないため、同じ条件で確認を繰り返せない。

## 完了条件

- 既存のAPIとフロントエンドについて、コード、設定、依存関係を対象とした初回のセキュリティ確認が行われ、対象、実施日、結果が記録されている。
- 新たに公開された既知脆弱性を再確認でき、同じ範囲の確認を手動で繰り返せる手順と実行環境が整っている。
- 確認の周期、担当、検出結果の評価・対応・再確認の方法が定められ、未解決の問題を追跡できる。
- 勉強用リポジトリとして、定期実行の自動設定を有効化せずに運用できる。

## 実装方法案

- APIとフロントエンドの既存のセキュリティ対策と検査コマンドを調べ、依存関係の既知脆弱性、ソースコード、設定の確認範囲を決める。
- 再実行可能な検査コマンドと手順を整備し、脆弱性情報の更新を反映して再確認できることを確かめる。
- 初回の確認を実施し、検出事項は影響と到達可能性を評価して、修正または期限付きのリスク対応として記録する。
- 月1回を候補に確認周期と担当を決め、手動実行の手順と結果の保存先を文書化する。
