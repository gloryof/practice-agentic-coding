# コマンドのコンテキスト境界を跨ぐ依存を解消する

## ステータス
- Status: Proposed
- Updated: 2026-07-11 - 起票

## 背景
`api/docs/architecture.md` は、コマンド側でコンテキスト境界を跨いだ依存を禁止している。一方、現行実装には `auth` から `libraryuser`、`reservation` から `libraryuser`、`libraryuser` から `auth` のドメイン型、Repository、Domain Serviceへの直接依存がある。

代表例として、認証アカウントが `libraryuser` のメールアドレスと図書館利用者IDを参照し、予約モデルが `libraryuser` の図書館利用者IDを参照している。また、図書館利用者登録のイベントハンドラーが `auth` の認証資格情報、Repository、パスワードハッシュ処理へ直接依存している。

## 影響
コンテキスト間でドメイン型とポートを直接共有すると、一方のモデル変更が別コンテキストへ伝播し、コンテキスト単位の変更、テスト、将来の分離が難しくなる。現状はアーキテクチャの `MUST NOT` に違反しており、新しい越境依存を一貫してレビューできない。

## 対応案
- 現在のコンテキスト境界を跨ぐimportを列挙し、識別子の共有と業務連携に分類する。
- 図書館利用者IDなどの安定した識別子を、コンテキスト固有の値オブジェクトとして変換するか、明示的な共有カーネルへ配置するか決定する。
- コンテキスト間の業務連携は、他コンテキストのDomainやRepositoryへの直接依存ではなく、連携用ポート、イベント、またはアプリケーション調停を介する。
- 決定した方式へ `auth`、`libraryuser`、`reservation` の既存依存を移行する。
- コンテキスト境界を跨ぐimportをCIで検出する静的検査を追加する。

## 確認方法
- `auth`、`libraryuser`、`reservation` のDomain、Usecase、Infraに、他コンテキストの `command` パッケージへの直接importがないことを確認する。
- 登録、ログイン、予約の既存テストとE2Eテストが成功することを確認する。
- コンテキスト境界違反を意図的に追加した場合、静的検査が失敗することを確認する。

## 期限 / 優先度
- 期限: 新しいコマンドコンテキストまたはコンテキスト間連携を追加する前
- 優先度: High
