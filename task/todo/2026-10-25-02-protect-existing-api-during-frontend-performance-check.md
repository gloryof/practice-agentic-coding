# フロントエンド性能検査で既存APIとDBを停止しない

`frontend/scripts/run-performance.sh`はポート8080が使用中でも既存APIへ接続し、終了時にそのリスナーと`agentic-postgres`を停止し得る。  
既存の開発環境を変更せずに検査を中止できるようにする。

## ステータス
- Status: Proposed
- Updated: 2026-10-25 - 性能検査の中断時に発見
- 優先度: 高

## 背景

2026-10-25に`npm run test:performance`を実行した際、API起動ランナーはポート8080の使用を検知して終了した。  
性能検査スクリプトは既存APIのヘルスチェックを成功と判断して処理を続け、終了処理で8080のリスナーを停止し、`agentic-postgres`を削除した。

## 課題

API起動ランナーが失敗しても既存リスナーを自分が起動したものとして扱うため、開発中のAPIやDBを予期せず停止する。  
性能測定の対象も、検査用に準備したAPIとDBだと保証できない。

## 完了条件

- ポート8080が使用中なら、既存APIとDBを変更せず、性能検査を開始前に失敗として終了する。
- 検査の終了処理が、自身の起動したプロセスと自身が準備したDBだけを片付ける。
- API起動失敗時に既存サービスを測定対象として使用しない。

## 実装方法案

- API起動前にポート8080を確認し、使用中なら理由を表示して終了する。
- API起動ランナーの成功と所有プロセスを確認してからヘルスチェックと計測へ進む。
- 既存APIが8080を使用する状態で検査を実行し、リスナーとDBが残ることを確認する。
