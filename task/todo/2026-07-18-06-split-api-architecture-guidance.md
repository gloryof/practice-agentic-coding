# APIアーキテクチャ規約を条件別に分割する

## ステータス
- Status: Proposed
- Updated: 2026-07-18 - 起票

## 背景
`api/docs/architecture.md` は、共通原則、例外処理、Command、Query、永続化、Web、可観測性などを単一文書で管理し、すべてのコード追加・修正・レビューで全文参照する条件になっている。

## 影響
変更に無関係な規約まで毎回読み込むため、API作業の初期コンテキストが大きくなる。文書がさらに成長すると、必要な規則を見つけにくくなる。

## 対応案
- 常に必要な共通原則と、Command、Query、エラー処理、Web契約、永続化、可観測性などの条件付き規約を分離する。
- `api/docs/backend-guidelines.md` に、変更対象と参照先の対応表を設ける。
- 規則の意味、規範レベル、既存ADRへのリンクを変えずに移動する。
- 同じ規則を複数文書へ複製せず、正本を一箇所に保つ。

## 確認方法
- Command、Query、テストのみ、DAOのみの代表変更で必要な文書だけを選択できることを確認する。
- 移動前の全規則がいずれかの正本文書に残り、重複や参照切れがないことを確認する。
- 既存のアーキテクチャテストと `./gradlew check` が成功することを確認する。
