# テーブル設計の方針を明文化

## ステータス
- Status: Done
- Updated: 2026-04-05 - 完了

## 背景
IDの型をアプリケーション責務で `String` とする方針など、
テーブル設計の判断基準が明文化されていない。

## 影響
開発者ごとに設計判断が揺れ、将来的な整合性や移行コストが増える。

## 対応案
- `api/docs/coding-rules.md` または設計ドキュメントに
  テーブル設計の基本方針（ID型、主キー命名、外部キー、長さ制約など）を追記する。

## 確認方法
- 方針が `api/docs/coding-rules.md` に明文化され、レビューで参照できること。

## 期限 / 優先度
- 優先度: 中
