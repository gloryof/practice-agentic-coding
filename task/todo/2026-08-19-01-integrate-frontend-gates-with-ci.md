# フロントエンド品質ゲートをCIへ接続する

## ステータス
- Status: Proposed
- Updated: 2026-08-09 - 起票

## 背景
`frontend/package.json`へ再現可能な品質ゲートを実装したが、利用するCI製品とワークフローは未決定であり、今回はnpm scriptsの整備までを対象とした。

## 影響
開発者がローカルでゲートを実行し忘れた場合、型、静的解析、テスト、build、Storybook、アクセシビリティの回帰を変更統合前に自動で防止できない。

## 対応案
- リポジトリで利用するCI製品を決定する。
- Node.js 24と`npm ci`を使用し、`npm run check`を必須ゲートとして実行する。
- 依存関係変更時に`npm run audit:signatures`と`npm run audit:high`を実行し、承認済み例外を期限付きで扱う。
- BFFまたは利用者機能の変更時は、変更条件に応じて実APIブラウザE2E、複数ブラウザ、性能検査を追加する。

## 確認方法
- 新規環境のCIでロックファイルどおりに準備でき、`npm run check`が成功することを確認する。
- 意図的な型エラーまたはテスト失敗で変更統合がブロックされることを確認する。

## 期限 / 優先度
- 優先度: CI製品の決定後、最初のフロントエンド機能変更まで
