# ドメインイベント保存責務のイベントハンドラー移管

## ステータス
- Status: Proposed
- Updated: 2026-05-23 - 起票

## 背景
- 現状、ドメインイベントの保存責務がユースケースやドメイン処理側に寄ると、ビジネス処理とイベント永続化の関心が混在しやすい。
- ドメインイベントは発生した事実を表すものであり、保存・配信準備などの副作用はイベントハンドラー側に集約した方が責務境界を保ちやすい。
- 今後イベント種類や後続処理が増えた場合、保存処理の呼び出し漏れや重複実装が発生するリスクがある。
- イベントで直接保存している箇所があるのでイベントからモデルを発行するようにしたい。

## 影響
- ユースケース層の処理フローがイベント保存の詳細に依存し、実装とテストの見通しが悪くなる。
- ドメインイベント追加時に、保存責務をどこへ実装するかの判断がぶれやすくなる。
- 保存失敗時の扱い、リトライ、監査ログなどの運用論点をイベント処理として整理しにくくなる。

## 対応案
- ドメインイベントを発行する側はイベント生成・発行に責務を限定し、永続化はイベントハンドラーで担う構成へ見直す。
- イベントハンドラー内でイベント保存リポジトリを呼び出し、保存対象・保存タイミング・失敗時の扱いを明確にする。
- 既存のイベント保存処理がある場合は、ユースケース側からイベントハンドラー側へ移管し、重複保存や保存漏れが起きないようにテストを追加する。
- 将来のイベント配信やアウトボックス化を見据え、保存されたイベントの状態管理が必要かを合わせて確認する。

## 確認方法
- ドメインイベント発行時に、イベントハンドラー経由でイベントが保存されることをテストで確認する。
- ユースケース側にイベント保存リポジトリへの直接依存が残っていないことを確認する。
- イベントハンドラーで保存失敗が発生した場合の期待挙動をテストまたは仕様で確認する。
