# APIアーキテクチャ方針変更依頼

Scenario ID: `07-api-architecture-policy`

Spring Boot APIのコマンド処理について、DBトランザクションとドメインイベントハンドラーの実行境界を明文化してください。

現在の前提と解決したい問題は次のとおりです。

- APIは単一プロセス、単一PostgreSQL、単一デプロイ単位であり、メッセージブローカーや外部通知サービスを使用していない。
- 1回の利用者操作で必要なDB更新が一部だけ確定することは許容しない。
- 現在のイベントハンドラーは同じアプリケーション内で別の永続化処理を呼び出すが、トランザクションの所有者、ハンドラーの実行時点、失敗時の扱いが規約から判断できない。
- 将来外部通知などを追加しても、外部I/Oの完了をDBトランザクション内で待つ設計にはしない。
- 現時点では新しいインフラを導入せず、導入を再評価する条件だけを定める。

Usecase、Repository、イベントハンドラーそれぞれの責務、トランザクションの開始・終了、同期処理とafter-commit処理の区別、失敗・再試行・冪等性、ログとトレース、テスト方針を含む方針案を作成してください。既存実装への影響、代替案とトレードオフ、必要なレビュー、整合確認、段階的な反映方法も示してください。
