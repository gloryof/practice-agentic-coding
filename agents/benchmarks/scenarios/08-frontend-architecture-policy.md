# フロントエンドアーキテクチャ方針変更依頼

Scenario ID: `08-frontend-architecture-policy`

認証済みの検索・一覧画面について、URL、Server Components、Client Components、BFFが所有する状態の境界をフロントエンド方針へ追加してください。

固定する要件と制約は次のとおりです。

- 確定した検索条件、並び順、ページ番号は、共有、再読み込み、戻る・進むで復元できるURL queryを正本とする。
- 送信前のフォーム入力、開閉状態、フォーカスなど一時的な操作状態だけをClient Componentが所有してよい。
- Server ComponentはURLから確定条件を読み取り、サーバー専用データアクセス境界を通じてSpring Boot APIの状態を取得する。
- ブラウザへBearerアクセストークン、サーバー専用設定、API応答の不要な内部情報を渡さない。
- 検索実行とページ移動はURL遷移として扱い、読み込み中、0件、再試行可能な失敗、認証切れを区別する。
- 古い応答で新しいURLの表示を上書きしない。
- 外部状態管理、クライアントデータキャッシュ、フォーム管理ライブラリは追加しない。
- Spring Boot API契約とユーザー向け業務ルールは変更しない。

既存のBFF、Client、状態・イベント管理、品質・非機能方針との責務重複を避け、更新する正本とリンク関係を示してください。代替案とトレードオフ、既存実装への影響、必要なレビュー、整合確認、段階的な反映方法も示してください。
