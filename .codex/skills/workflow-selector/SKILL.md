# ワークフロー選択

## 目的

ユーザーがタスクを説明した後、適切な定義済みワークフローを提案する。  
ユーザーが選択または別のフローを指定してから、そのフローの手順に従ってタスクを進める。

## 手順

1. ユーザーが実行したいタスクをまだ説明していない場合は、内容を尋ねる。  
   すでに依頼文から明らかな場合は聞き直さず、次へ進む。
2. リポジトリルートの `AGENTS.md` にある「定義済みワークフロー」のタイトルと定義文書パスを正本として確認する。  
   選択前に参照するのはタイトルだけとし、タスクとの対応を判断できないときに限って候補の目的・適用範囲を確認する。
3. タスクの成果物と変更対象をもとに最適な候補を一つ選び、候補名と定義文書パス、そのタスクに適合すると考えた理由を短く提示する。  
   該当する候補がなければ「ワークフローを適用しない」を提案する。
4. 提案をユーザーに示し、選択を待つ。  
   ユーザーが別候補または独自のフローを指定した場合は、その指定を採用する。  
   選択前にフローの詳細手順やスキルを読み始めたり、タスクの実作業を始めたりしない。
5. 選択されたフローの定義文書を読み、タスクへの適用範囲を確認する。  
   適合する場合は、その手順と参照規約に従ってタスクを進める。
6. 選択されたフローがタスクに適合しない場合は、適合しない理由を説明し、別の定義済みフローまたは「ワークフローを適用しない」の再選択を依頼する。  
   ユーザーが独自のフローを指定した場合は、利用可能な指示や文書を確認して従う。
7. 「ワークフローを適用しない」が選択された場合は、リポジトリと対象ディレクトリの共通規則に従い、依頼に必要なスキル・参照・検証を判断して進める。

## 候補の判断

- `ユーザーストーリー作成フロー` は、ユーザーストーリーを新規作成する依頼に提案する。
- `ドメインモデル実装フロー` は、ドメインモデル、イベント、制約、ユースケースの仕様作成・更新や、そのドメイン層・ユースケース層の実装を含む依頼に提案する。
- `アダプター実装フロー` は、Web・Infraアダプター、DB変更、アプリケーションへの接続を含む依頼に提案する。
- 一つのタスクが複数のフローにまたがり、正本の適用範囲だけでは一つに絞れない場合は、候補と境界を示してユーザーに選択を求める。  
  適用範囲の確認前に複数フローを連結したり、対象範囲を拡張したりしない。
- ワークフローのタイトルや定義文書パスを推測で追加・変更しない。  
  定義文書が見つからない場合はその旨を伝え、ユーザーに確認する。

## 選択後の引き継ぎ

選択後は選んだフローの指示に従う。  
このスキルはフロー選択を支援するもので、フローが要求する規則、参照、レビュー、検証を省略する根拠にはならない。  
作業中に別フローの適用範囲に入る変更が必要と判明した場合は、自動で範囲を広げず、現在のフローの規則に従って扱う。
