# Agentワークフローベンチマーク

## 責務

このスキルを使用するAgentは計測Coordinatorとして振る舞う。シナリオの作業を自分で実行せず、実行条件の固定、隔離した作業Agentの起動、取得情報の分類、結果保存を担当する。結果テンプレートのMain Agentは作業Agentを指し、Coordinator自身のコンテキストは計測値へ含めない。

具体的な固定シナリオの作業と参照履歴の報告を同時に求められている場合、そのAgentは作業Agentである。このスキルによるシナリオ選択、別Agentの起動、結果保存を行わず、与えられた固定入力の作業だけを続ける。

最初に次を参照する。

- `agents/benchmarks/README.md`
- `agents/benchmarks/RESULT_TEMPLATE.md`
- 実行対象の`agents/benchmarks/scenarios/<scenario-id>.md`

通常は`pre-work`を使用する。`full-run`はユーザーが明示し、かつシナリオが許可している場合だけ使用する。

## シナリオの選択

- ユーザーがBaseline IDを指定した場合は、そのIDを使用する。
- Baseline IDが指定されていない場合は、同じ対象コミット、実行モード、正式・試運転区分に一致する未完了のBaseline IDを再利用する。該当するものがなければ、実行日、対象コミットの短縮SHA、実行区分を識別できるIDを作る。
- ユーザーがシナリオIDを指定した場合は、そのシナリオを使用する。
- シナリオIDが指定されていない場合は、定義済みシナリオをID順に確認し、選択したBaseline IDに結果がない最初のシナリオを使用する。対象がなければ、定義済みシナリオの実行が完了していることを報告する。
- 未コミット変更がある実行は`pilot`として扱い、正式な基準値と区別する。
- READMEで初回試運転または手順検証と定める実行も、作業ツリーの状態にかかわらず`pilot`として扱う。
- 正式基準値に不採用となった結果を含むBaseline IDは再利用せず、新しいBaseline IDを作る。
- 一度の呼び出しでは一つのシナリオだけを実行する。すべてのシナリオを求められた場合も、一つずつ独立した作業Agentで実行する。

## 実行条件の固定

作業Agentを起動する前に、対象コミットの完全なGit SHA、作業ツリーの状態、モデル、reasoning設定、利用可能なツール、実行環境、開始日時を記録する。取得できない値は推測せず`not_available`と理由を残す。

正式な基準値は、ベンチマーク定義を含むコミットのクリーンな作業ツリーで実行する。未コミット変更がある場合は試運転を継続してよいが、正式な基準値として扱わない。

## 作業Agentの起動

会話履歴を継承しない独立した作業Agentを起動する。sub-agent機能を使用する場合は`fork_turns`を`none`にする。独立した作業Agentを利用できない場合は、Coordinator自身で代行せず、計測条件を満たせないことを報告して停止する。

作業Agentへ渡す情報は次だけに限定する。

1. `agents/benchmarks/README.md`の「固定の計測報告契約」に定める本文。
2. シナリオファイルの本文を改変せず転記した固定入力。

本スキル、ベンチマークREADME、結果テンプレート、過去結果、シナリオの作成経緯、Coordinatorの会話履歴は渡さない。

`pre-work`では、作業Agentにファイルを変更させない。`full-run`ではREADMEに定める隔離方法と変更範囲を守らせる。

## 結果の作成

作業Agentの成果物と報告を`agents/benchmarks/RESULT_TEMPLATE.md`へ転記し、対象コミット時点の適用規約に照らしてコンテキスト取得イベントを分類する。

- 実トークンを取得できない場合は、代替指標を実トークン欄へ入れない。
- 観測できなかった参照や内部処理を推測で補わない。
- 呼び出したスキルと参照したドキュメントの一覧を省略しない。該当しない場合も`なし`と理由を書く。
- 作業Agentとレビュー担当が分かれる場合は、Actorごとに記録を分ける。
- 固定入力、必須規約、成果物、予定レビュー、予定検証の欠落を品質評価へ反映する。
- 初回試運転または手順上の欠陥が見つかった実行は、成果物品質が合格でも正式基準値には不採用と記録する。

結果は`agents/benchmarks/baselines/<baseline-id>/<scenario-id>.md`へ保存する。既存結果を上書きせず、Run IDまたはBaseline IDを変更する。保存後はローカル絶対パスが含まれないことを検査し、この実行で作成した結果ファイルだけをステージする。

## 停止条件

次の場合は、結果を正式な基準値として確定せず理由を報告する。

- 会話履歴を継承しない作業Agentを利用できない。
- 対象シナリオが未定義、または固定入力を特定できない。
- `full-run`に必要な隔離環境を用意できない。
- 既存結果を上書きせず保存できない。
